# EmbeddedQuiz 嵌入式面试助手

原生 Kotlin / Jetpack Compose Android 应用，离线题库和学习记录使用 Room 保存，无账号和服务器依赖。Android 8.0（API 26）及以上可用。DeepSeek 是用户主动触发的可选联网功能。

## 工程与构建

技术栈：Kotlin 2.0 + Jetpack Compose（Material 3）+ Room，AGP 8.7.3，Gradle 8.9，compileSdk/targetSdk 35，minSdk 26，JDK 17。

### 本机离线构建（推荐，不需要 Android Studio）

这台电脑上已经有完整的工具链和依赖缓存，直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1
```

默认执行 `assembleDebug testDebugUnitTest`。也可以在脚本后面写任务名，例如只打包时加 `assembleDebug`。生成的 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，发到手机即可覆盖安装。

`tools/build.ps1` 使用以下位置，都可以用环境变量改：

| 用途 | 默认位置 | 环境变量 |
| --- | --- | --- |
| JDK 17、Android SDK（platform 35 / build-tools 35.0.0）、Gradle 8.9 | `C:\Users\woziji\Documents\Codex\2026-10-21\embeddedquiz-app-embeddedquiz-android-app-linux-5\work\toolchain` | `EQ_TOOLCHAIN` |
| 签名文件 `debug.keystore`（作为 `ANDROID_USER_HOME`） | 同上的 `work\android-home` | `EQ_ANDROID_HOME` |
| Gradle 依赖缓存（脚本带 `--offline`） | 同上的 `work\gradle-home` | `EQ_GRADLE_HOME` |
| 纯英文路径的目录联接 | `C:\AndroidProjects\EmbeddedQuiz` | `EQ_ASCII_LINK` |

源码路径含中文时，测试进程加载不到测试类（每个测试都报 `ClassNotFoundException`）。脚本会自动在 `C:\AndroidProjects\EmbeddedQuiz` 创建一个指向源码的目录联接，从那里构建。联接只是一个入口，删掉它不影响源码。

### 签名：保持覆盖安装的关键

项目没有自定义 `signingConfigs`，Debug 包由 `ANDROID_USER_HOME\debug.keystore` 签名。所有已发布 APK 的签名证书 SHA-256 都是：

```
2c73c905e6d127dd92fbfaf5351058572cb8e78e98beb477eb1a0f37ee43b151
```

- 必须用这个 keystore 构建，否则手机会拒绝覆盖安装，应停止安装并保留原应用/数据，先核对签名与备份，不要以卸载清数据绕过。仓库外的 `..\signing-backup\debug.keystore` 存有一份备份；`*.keystore` 已列入 `.gitignore`，不要提交。
- 不要修改 `applicationId = "cn.embeddedquiz"`。每次发版把 `versionCode` 加 1。
- 交付前用 build-tools 里的 `apksigner verify --print-certs` 核对证书，用 `aapt2 dump badging` 核对包名和版本号。

### 其他方式

- Android Studio：打开本目录即可，`gradle.properties` 已设置 `android.overridePathCheck=true`。如果测试同样报 `ClassNotFoundException`，从纯英文路径打开项目。
- 命令行：`.\gradlew.bat assembleDebug testDebugUnitTest lintDebug`，Linux/macOS 用 `sh gradlew …`。首次构建会从 Google Maven、Maven Central 下载依赖。`local.properties` 记录本机 SDK 路径，不应提交到 Git。

## 开始使用

1. 安装 Debug APK。首次启动自动导入随包题库，不需要网络。
2. 首页可开始新题、顺序练习、随机练习或到期复习。
3. 分类页可搜索题干/答案，并按来源、公司、知识点、题型和难度筛选。
4. 先作答，有可靠标准选项的题目提交后直接判分并保存；其他题目查看参考后，选择“正确 / 错误 / 不会”保存记录并安排复习。无法自动判分的题目仅查看参考不会计为完成。
5. 编程专区自动保存代码和笔记草稿，可缩进、复制和计时；个人参考解法须手动保存并确认。手机不执行代码、不提供联网判题。
6. 底部“更多 → 设置”可调整主题、字号、目标和提醒，导入 JSON、导出备份或恢复备份。新版完整备份包含便签与独立个人资料，不含 Key；恢复前有确认提示。
7. 答题时点击“打开便签”，或“更多 → 便签”切换到独立便签区。输入自动保存，点击“全部便签”浏览和搜索，点击“继续答题”返回原题。模拟考试在便签页仍继续计时。

## 随包题库与可信度

随包共 906 条：分类合集 498 条，普特面试题 306 条，手写代码 41 条，严选原创练习 61 条。经题型分流后，日常 827 条，编程专区 79 条；保留 4 张嵌入图片。

- 分类合集原文没有答案；新版通过《嵌入式面试题合集_选择题答案与解析.docx》补充 152 条答案和解析，题号、来源、题干及选项逐一匹配。67 条答案明确且选项有效，可自动判分；85 条存在限定条件、歧义或选项缺失，仍待核对；另外 346 条未提供答案。没有编造答案。
- 普特题库保留原始参考答案与代码，不代表经过逐条技术事实认证。可在应用内质疑并标记待核对。
- 相同题目仍保留独立来源和进度，以 `duplicateOf` 记录关联，不从普特答案自动填充公司题答案。
- 原文没有难度等级，因此显示“未标注”。外部 JSON 可提供难度。
- 填空题以简答自评；含“不定项”的选择题按多选处理；可靠答案包含多个选项时改为多选；其余未注明的题目按单选展示，待核对题不自动判分。
- 编程题来源的题目，以及重复题干对应的编程题均从日常题池排除。简答题中的原理描述、驱动实现流程仍留在日常题池。
- 原文未单列的样例、约束、思路或参考代码显示缺失提示；完整题干仍保留，AI 不会写入原始字段。

严选导入报告见 `app/src/main/assets/bank.yanxuan-report.json`，题干和答案保留原文定位，三组重号按组独立匹配。文档中的对话引言和后续邀请不导入。

手写代码导入报告见 `app/src/main/assets/bank.handwritten-report.json`。该清单中 49 个题目正文段落按多步骤关系组成 41 条，题目中的疑似笔误、不完整条件和缺失接口原样保留。

原始导入报告见 `app/src/main/assets/bank.report.json`，新版答案合并报告见 `app/src/main/assets/bank.answers-report.json`，当前整包审计见 `source-audit.json`。每题附原文文件名、正文块位置和来源信息，可回查原文。`raw` 保留原始正文；代码按原文换行与空格保存；图片以 Base64 嵌入 JSON，因此备份和导入无需维护外部图片目录。

## 模拟考试与判分

仅从非编程、具有已核对标准选项的客观题抽题。支持 10 / 20 / 50 题、15 / 30 / 60 分钟；不足题量时使用所有符合条件的题目。选择异步保存并显示状态；计时使用截止时间，关闭重开恢复已落盘内容。时间到或交卷后统一判分，仅非空作答生成学习记录；未答题计零分但不改变复习安排，确认放弃不记学习记录。同一场考试重试/恢复通过持久化终止台账防重复记账。

单选和判断答案完全匹配；多选按集合完全匹配，漏选、多选、错选均错误。有效的个人核对答案优先于原题库已核对标准选项；自动判分结果不可在提交时用自评覆盖。无标准选项、待核对和主观题不自动判分，需手动选择正确、错误或不会。正确按原“记住了”的间隔规则安排；错误和不会均加入错题本并在次日复习，历史中分别标记。后续答对会移出错题本；“不会”筛选依据最新记录。

**新版随包有 128 道可自动判分的客观题，可直接用于模拟考试。** `tools/sample_bank.json` 提供 3 道清楚标为“功能验证示例”的独立演示题，覆盖单选、多选、判断，未混入原题库。可导入它来试用自动判分和考试；需要实际笔试训练时导入自己核对过的答案题库。

## 复习算法

采用可解释的 SM-2 变体。日期以当前设备本地 `LocalDate` 的 epoch day 保存，不按固定 24 小时做毫秒累加，因此闰年、跨月和夏令时不会造成日期偏差。

当前界面仅要求正确或错误（手动题另有不会），内部沿用 SM-2 的 GOOD / AGAIN 排程。HARD / EASY 仅用于兼容旧历史记录和旧排程测试，当前答题不再展示。原算法定义如下：

|内部反馈|质量分|安排|
|---|---:|---|
|忘记了|1|连续掌握次数归零，1 天后复习，遗忘次数加一|
|困难|3|初次 1 天、第二次 3 天，之后按系数 × 0.8 延长|
|记住了|4|初次 1 天、第二次 6 天，之后乘难度系数|
|简单|5|初次 4 天、第二次 6 天，之后乘难度系数 × 1.3|

难度系数更新：`EF' = clamp(EF + 0.1 - (5-q) × (0.08 + (5-q) × 0.02), 1.3, 3.5)`。初值 2.5，长期复习最多间隔 3650 天。正确采用质量分 4；错误和不会采用质量分 1。到期列表优先展示错题，再按到期日排列。

首页区分未学新题、今日新学、今日到期复习完成与总完成题数。简答题的正确记录属于自评；统计页明确区分未判分题。重置会清除学习次数、排程和答题历史，保留收藏、质疑标记、笔记、代码及 AI 缓存。

## DeepSeek

设置页输入自己的 API Key，选 `deepseek-flash` 或 `deepseek-v4-pro`。请求固定发送到官方 `https://api.deepseek.com/chat/completions`，禁用重定向以避免凭据转发。

Key 使用 Android Keystore 中的 AES 密钥进行 AES/GCM 加密；共享偏好仅保存密文和 IV。应用不记录 Key，不包含网络日志拦截器，系统自动备份已禁用，手动备份不导出凭据。清除应用数据或卸载会丢失密钥，需要重新输入。

点击 AI 按钮才发送题干、选项、原始参考答案、所选选项与最近四轮讨论。可要求详细解析、错因分析、举例、代码分析或质疑。AI 解析存于独立 `ai` 表，不更新 `questions`。独立详细解析按模型和完整输入缓存；追问缓存还包含讨论上下文。网络失败、超时、鉴权/余额错误、限流、服务端错误和异常响应均显示错误提示，不影响离线功能。

费用估算使用 2026-10-23 核对的官方 USD 高峰费率，分别计算输入缓存命中、未命中与输出；实际费用以 DeepSeek 账单为准。缓存命中不增加本地 token 统计。费率常量可在 `Ai.kt` 更新。

```powershell
python -m pip install -r tools/requirements.txt
python tools/import_docx.py "嵌入式面试题合集_分类整合版.docx" "普特面试问题汇总v2.3_全部问题解答.docx" --out bank.json

python tools/import_yanxuan.py bank.json "严选.docx" --out bank.json
python -m unittest discover -s tools -p "test_*.py" -v
```

导入器针对本次原始两份文档的 `题目NNN` / `Question` 样式与章节结构实现。读取正文段落与表格顺序，提取内嵌图片，保留原始代码缩进；按规范化题干及选项检测精确重复，保留重复来源。不会执行文档中的命令或指令。

后续不同 Word 版式需要扩展解析规则并检查报告，不能假定任意 Word 都能无损自动识别。应用导入统一 JSON：根对象有 `schemaVersion: 1`、`questions` 数组；字段示例见 `tools/sample_bank.json`。题型：`SINGLE`、`MULTIPLE`、`TRUE_FALSE`、`CODE_READING`、`SHORT`、`PROGRAMMING`。必须提供唯一 `id`、非空 `stem`、`source`、有效 `kind`。可靠客观题需 `reviewRequired: false` 和有效选项键集合 `correct`。

文件选择器导入按相同 ID 跳过。随 APK 更新的内置题库有独立版本号，匹配相同 ID、来源与题干后仅更新题目内容，不修改学习数据。旧版备份仍可恢复；恢复旧备份会恢复其中的旧答案。导入前校验整包，备份恢复在 Room 事务中整体执行，格式错误不应留下半份数据。文件上限 32 MiB、单包最多 20000 题。

## 架构与扩展

- `Domain.kt`：题型、精确判分、复习日期算法和 `JudgeService` 扩展接口。
- `Data.kt`：Room 九张表（含考试终止台账）、摘要索引、SQL 聚合、JSON 校验及无损迁移。
- `Repository.kt`：答题事务、进度更新、导入和备份恢复。
- `QuizViewModel.kt`：MVVM 状态、异步任务、考试状态和 AI 缓存调度。
- `MainActivity.kt`：Compose 页面。
- `Ai.kt`：凭据保护、HTTP 客户端、错误映射和费用估算。

Room schema 已启用导出。未来改表需增加版本并编写迁移，工程没有开启破坏性迁移。未来编译/判题服务通过 `JudgeService` 接入；当前 `UnavailableJudge` 明确返回不可用，不伪装判题成功。

测试与实际执行结果见 `VALIDATION.md`。
