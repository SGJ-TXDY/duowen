## 3. P1 详细任务

### T1：未答题不再污染学习记录，并提供放弃考试

**已确认问题**：ExamStateHolder.grade 遍历整卷，对没有选择的题也调用 record，造成 seen/lapses 增加、连续掌握归零、interval 变为 1、进入错题本。现有确认框未说明该后果。

**业务裁定**：

- 未答题考试计零分，成绩分母仍为整卷题数。
- 未答题不创建学习作答记录，不改变 Progress/SRS/错题或每日完成统计。
- 已答正确/错误继续沿用现有学习规则。多选漏选但非空属于已答错误；清空到空集合属于未答。
- 提供“放弃本次考试”，二次确认后关闭会话，不产生学习记录。
- 不修改普通练习和手动自评的判分语义。

**GPT 修改范围与要求**：

- `ExamStateHolder.kt`：区分未答/已答，生成明确结果数据，交卷只记录已答题。
- `QuizViewModel.kt`：仅考试完成/放弃相关方法，返回或发布可观察结果与操作状态。
- `Repository.kt`：仅确有必要的考试支持，不改变通用 record 的空答规则来绕过问题。
- `app/src/test/...`：考试评分、排程隔离、放弃和重复提交测试；允许在现有测试目录新增专用测试文件。
- 先定义结果模型至少包含 total/answered/unanswered/correct/score，以及完成/失败语义，供 Claude 展示。

**Claude 修改范围与要求**：

- `QuestionScreen.kt`：交卷确认、成绩展示、放弃确认；明确未答计零分但不改变复习安排。
- `BrowseScreen.kt`/`ExamScreen.kt`：未完成考试入口提供继续和放弃，避免误操作；按实际承载函数修改。
- 对应 UI 测试：确认/取消、忙时禁用、防连点及返回行为。
- 不自行计算或写入 SRS，不把放弃实现为“空答交卷”。

**验收标准与测试方法**：

1. 构造 50 题，只答 10 题：总分分母为 50，新增 Attempt 恰为 10。
2. 对其余 40 题逐字段比较，已有 Progress 完全不变，无记录的题不生成 Progress。
3. 全未答、全答、部分答、多选漏选、多选清空、超时与手动交卷均覆盖。
4. 放弃后会话不恢复，Attempt/Progress 不变；取消放弃继续原考试。
5. 连续点击交卷不重复记录；普通练习相关测试全部通过。
6. T1 的按钮防重复测试不能替代 T2 的跨进程幂等测试。

### T2：考试快照异步持久化与完成协议

**已确认问题**：UI 选择 → answerExam → saveExam → writeDurably → runBlocking(IO) → commit，主线程仍等待；成绩事务与偏好快照清除不是同一提交点。

**GPT 修改范围与要求**：

- `ExamStateHolder.kt`、`QuizViewModel.kt` 考试保存/恢复/完成方法；可增加同包下职责单一的考试写入组件。
- `DurablePreferences.kt` 只有明确需要时修改，必须检查全部调用方，禁止全局改变已有完成保证。
- 内存答案立即更新；后台有序持久化，旧版本不能覆盖新版本。
- 区分 Saving/Saved/Error，定义“保存完成”的确切含义，暴露重试入口。
- 开始、交卷、放弃、离开关键边界提供 suspend 完成屏障；不得在主线程 runBlocking 等待。
- 用不可变快照/版本号固定提交输入；结束后迟到保存不能复活考试。
- 成绩提交具备幂等协议：覆盖成绩已写入但会话清除失败/崩溃窗口。方案若需结构变化先送审。

**Claude 修改范围与要求**：

- `QuestionScreen.kt`、考试入口页面：展示保存中/成功/失败，支持重试。
- `AppNavigation.kt`、必要的 `MainActivity.kt` 生命周期接入：调用已约定的异步命令，禁止自行读写 prefs。
- 结束操作过程中提供明确状态并阻止冲突操作；不能只用 toast 假称保存成功。
- 不承诺进程被立即杀死时尚未落盘的内容也能恢复。

**验收标准与测试方法**：

1. 注入 500ms 写入延迟，主线程事件仍可推进，点击不会等待磁盘；配合线程/事件断言，不只检查 IO 调度器。
2. 快速连续改变选择、切题后重开，最后成功提交的快照准确恢复，顺序和截止时间不变。
3. 保存失败可见且可重试，失败期间不得显示 Saved。
4. 在“成绩事务已提交、会话未清除”处注入故障，再创建新实例恢复并完成：学习记录仍只写一次。
5. 保存与交卷/放弃竞态、迟到保存、连续重试均不复活已结束会话。
6. 凭据持久化、模型设置及现有考试恢复测试不回归。

### T3：解耦历史迁移校验并建立启动错误恢复

**审计限定**：迁移调用当前 BankCodec 的问题存在；但对比 1.3.0，关键校验当时已存在。不得声称已经证明 v4 新增校验拒绝正常旧数据。真实缺口是迁移与可变化业务规则耦合，以及初始化失败后无恢复页面。

**GPT 修改范围与要求**：

- `LearningMigration.kt`：使用明确的历史读取/索引构建规则，不随外部导入校验器变化。
- `Data.kt`：必要迁移接入；外部 JSON 导入继续严格校验。
- `QuizViewModel.kt`：初始化 Loading/Ready/Error 状态、诊断与重试接口；必要的故障恢复服务。
- 如容忍历史异常条目，必须同时处理后续索引、题目读取和启动重索引，不能只让 migrate 返回成功。
- 原始 JSON 及用户记录保留；不可解释内容明确标记，不伪造成可判分题，不静默跳过删除。
- 恢复接口必须能在数据库未成功打开时工作或明确报告限制；保留旧数据的诊断/恢复路径先设计后实施。

**Claude 修改范围与要求**：

- `AppNavigation.kt` 启动分支，必要的独立错误页面；不改整体导航结构。
- 区分加载与失败，显示可理解原因、诊断入口和重试。
- 按接口接入备份恢复；涉及替换数据必须说明影响并确认。
- 错误页不依赖 ready=true 才可访问；不能用自动清数据解决启动失败。

**验收标准与测试方法**：

1. 文件型数据库测试 1→4、2→4、3→4，升级前后原始 JSON、收藏、代码、笔记、便签、历史和 AI 缓存保持。
2. 构造坏 JSON、未知题型、无效选项等历史数据，按裁定方案进入可恢复状态或明确失败；不无限加载、不自动删库。
3. 合法旧数据完整迁移；外部导入相同无效内容仍拒绝。
4. 初始化故障、重复重试、故障解除后成功都有测试，避免启动多个重复订阅。
5. UI 测试确认错误页能访问诊断/重试，恢复失败保留原数据。
6. 已为 v4 的数据库继续正常启动；不要仅覆盖尚未升级用户。

### T4：按题目合并草稿写入，保证最终内容与生命周期边界

**审计限定**：现有代码每次回调写当前 Progress 单行，并触发全量进度查询风险，不是每次写整张表，也不保证固定刷新 906 行。性能结论需测量。

**GPT 修改范围与要求**：

- `OrderedWriter.kt` 中 CodeDraftStateHolder 及必要扩展；`QuizViewModel.kt` 草稿保存、备份/恢复等边界。
- `Repository.kt`/`Data.kt` 仅必要字段级写入或订阅优化，不迁移整个进度存储。
- 按题合并短时间内变化，可从约 300ms 尾沿策略开始，并设最大等待时间，持续输入不能无限延迟保存。
- 相同文本不重复入队。优先限制代码草稿策略，不擅自改变便签删除和速记写入顺序。
- flush 必须包含尚在合并窗口内的最新草稿，并能报告失败。
- 保存读取最新记录，仅修改 code/notes，保留收藏、排程和计数；恢复/重置与迟到写入有明确隔离。
- 明确待保存、已落盘、失败三种状态；退出时关闭队列不视为已完成保存。

**Claude 修改范围与要求**：

- `CodeEditor.kt`、`QuestionScreen.kt`：即时编辑反馈、保存状态、错误重试、切题/离页接入。
- 必要生命周期接入限定在既有 UI 文件内；不自行决定数据库写入频率。
- 光标移动不应制造相同文本保存请求，输入法组合文本和缩进保持正确。
- 禁止把仅存在内存中的草稿显示为“已保存到本机”。

**验收标准与测试方法**：

1. 用可控时间连续输入同题 100 个版本（如每 10ms 一次），最终文本完全一致；明确写入上限，建议该样例不超过 5 次，具体值在方案中固定。
2. 持续输入超过最大等待时间仍有阶段性保存；最后一版必须落盘。
3. A/B 题交替编辑，均保留自己的最终内容；同文本更新不产生额外写入。
4. 输入后立即切题、离页、显式保存或导出备份，最终草稿正确；注入失败不能伪报成功。
5. 重试旧失败项不能覆盖较新的成功内容；恢复后迟到旧草稿不能写回。
6. 与收藏/判分并发，非草稿字段不丢；便签删除顺序和速记位置测试通过。
7. 真机长代码输入记录延迟与写入频率；没有设备时标记待验收，不以主观判断宣称已解决卡顿。

### 8.2 必须补齐的接口与状态边界

**A. 显式重试与超时触发分离。**

新增主线程门面 `retryExamOperation(): Unit`，只重试当前 Failed 对应阶段，返回不表示完成；Claude 后续的重试按钮调用此接口。`finishExam()` 在 Failed 状态不自动重试，也不重复刷 notice；现有每秒超时回调不能造成失败后每秒再次提交/清理。Submitting/Abandoning 和已终止状态的重复 finishExam 均无副作用。未知/无失败状态的 retry 必须拒绝或无操作，不创建新考试。

**B. 未提交记录的失败不能把用户锁死在坏考试中。**

- Failed(SUBMIT, VALIDATION/RECORDS, recordsCommitted=false)：可以显式重试原冻结输入，也可以经用户二次确认后调用 abandonExam；不能开放继续修改已经冻结的提交输入。
- Failed(SUBMIT, SESSION_CLEAR, recordsCommitted=true)：只能重试会话清理，不能放弃、重新评分或改答案。
- Failed(ABANDON, SESSION_CLEAR, recordsCommitted=false)：只能重试放弃清理，不能转成交卷。
- 校验失败和事务回滚后，abandonExam 必须可用，否则缺题/失去判分资格的考试会无法结束。

**C. 会话锁定不能依赖 prefs.contains。**

commit=false 可能已改变 SharedPreferences 内存值。结束操作中或任何待处理失败状态下，start/startExam、answerExam/saveExam 必须按当前内存会话状态拒绝冲突，不能因为 prefs.contains("exam")==false 就开启新练习或重建考试。仅允许为此调整 QuizViewModel 的考试入口守卫，不改全局 busy 调度。主线程受理的操作固定会话/输入，重试不能使用后来变化的页面 index 或队列。

**D. 取消保护有边界，不能将超出生命周期的工作伪装为可靠保存。**

取消发生在临界段前时，释放本次操作占用，不能遗留永久 busy/Submitting。取消保护只覆盖本次事务结果确定、提交标记及清理尝试，不包住整个 ViewModel 或无限重试。必须考虑 onCleared 同时关闭数据库：失败时诚实报告/保留已知状态，不声称 T1 保证进程结束后仍完成操作。若实现要求改造数据库生命周期或跨进程协议，先报告并留给 T2，不能扩大范围。

**E. 查询刷新不影响提交结论，兼容字段必须确定。**

学习记录成功后，不再依赖额外 historyPage 查询才能发布结果。正式 API_CONTRACT 写明每个状态下 examFinished、examSummary、examResult、队列/答案/截止时间的值或保留规则。清理失败必须冻结考试写入口，即使为兼容旧 UI 暂时保留 examFinished=false，也不能继续接受作答。放弃成功撤销考试上下文且不伪装成已评分；路由由 Claude 决定。

### 8.3 必加验收场景

除原 T1 与方案稿测试外，增加：

1. 缺题或资格校验失败 → 不写学习数据 → 确认放弃成功 → 新实例不恢复。
2. 事务失败回滚 → 可明确重试或放弃；失败不改变原有记录。
3. 已提交但清理失败 → 多次模拟超时 finishExam 不触发重试、不新增记录；显式 retryExamOperation 仅清理。
4. 假 SharedPreferences 在 commit=false 时已删除内存 exam 键 → 仍不能开始新练习/考试；正确重试后才解锁。
5. 放弃清理失败不能被超时回调转成交卷；成功结束后迟到 save/answer 无副作用。
6. 临界段前取消不留下永久忙状态；临界段中取消和数据库关闭按实际结果验证，不用单纯 sleep 推测顺序。

QuizViewModel 新增只读可观察属性与 Main 入口：

```kotlin
sealed interface ExamSaveState {
    data object Inactive : ExamSaveState
    data class Saving(val revision: Long) : ExamSaveState
    data class Saved(val revision: Long) : ExamSaveState
    data class Error(val revision: Long, val message: String) : ExamSaveState
}
val examSaveState: ExamSaveState
fun retryExamSave(): Unit
suspend fun flushExamSave(): Boolean
```

- 保留 startExam、answerExam、saveExam、finishExam、abandonExam、retryExamOperation 的既有签名和 T1 操作状态/成绩接口。前三个入口受理内存更新与排队后立即返回，不做主线程磁盘等待。
- revision 在会话内递增；异步任务捕获不可变副本，包括会话 ID、题号顺序、index、deadline、answers。Saving 表示最新版本未确认持久化；Saved 仅表示当前最新版本已可靠落盘，旧完成不能覆盖新状态；Error 保留最新待保存数据。Inactive 表示没有待保存活动考试，不等于持久化失败被忽略。
- 保存状态独立于 examOperationState/busy：普通后台保存不占全局 busy、不阻塞继续选择和翻题；结束操作及 T1 Failed 仍冻结答案。Error 时允许继续作答，必须持续提示未保存；新修改可触发一次新的保存尝试，但无新修改时不无限自动重试。retryExamSave 只显式重试当前活动会话最新快照，终止会话无副作用。
- flushExamSave 从 Main 协程调用，挂起等待、不阻塞线程；捕获调用时会话及 revision，确保此前受理的数据已落盘或被同一会话更高版本覆盖，成功 true。无活动/待保存考试 true；保存失败 false 且保留 Error；调用方取消向上传播，不取消已受理的持久化队列。不能返回成功后却只写了更旧版本。
- startExam 的第一份快照立即入队，未落盘显示 Saving，不伪报已保存；在 durable 会话身份和提交快照成功建立前不允许写成绩。开始不要求新建公开 suspend API。

- 放弃不要求先把全部答案保存成功：先隔离/排空该会话在途写入，再建立持久化终止标记、清理快照。失败走现有 ABANDON/SESSION_CLEAR；不得因保存故障永久无法放弃。

## 18. T4 正式派发：代码草稿合并写入与保存边界

### 18.1 范围与策略

问题是每个文字变化都写 Progress 单行，并可能触发全量查询/Map 刷新，不是“每字符写全表”。先减少实际写入，不在本任务顺带重构所有 Flow/DAO 或文件布局。适用于现有 CodeDraft 的 code/notes 自动草稿和显式保存调用；普通题笔记原有“点击保存”行为保留，不擅自扩大自动保存范围。

固定策略：按题合并，**尾沿 300ms、从该题最早未保存改动计最长 2000ms**；每次修改不能重置最大等待时钟。一个执行中的串行写入加每题一个最新待写版本，待写版本替换而非每字符无限排队。相同 code/notes 不增加 revision 或额外写入；纯光标/选区变化不触发后端更新。UI 内容即时反馈，JSON/数据库工作不阻塞 Main。

优先新增草稿专用组件，把 CodeDraftStateHolder 切换到专用策略；通用 OrderedWriter 本体和便签/速记协议默认保持。CodeDraft/CodeDraftStateHolder 留在原位置也可，不开展目录重组或数据库版本变更。

### 18.2 固定目标接口（Architect 已裁定，待 GPT 实现）

QuizViewModel 对外新增：

```kotlin
sealed interface CodeDraftSaveState {
    data object Inactive : CodeDraftSaveState
    data class Saving(val revision: Long) : CodeDraftSaveState
    data class Saved(val revision: Long) : CodeDraftSaveState
    data class Error(val revision: Long, val message: String) : CodeDraftSaveState
}
fun codeDraftSaveState(id: String): CodeDraftSaveState
val codeDraftEditingBlocked: Boolean
fun updateCodeDraft(id: String, code: String, notes: String): Unit
fun retryCodeDrafts(id: String? = null): Unit
suspend fun flushCodeDrafts(id: String? = null): Boolean
```

接口语义：

- Main 调用，状态必须被 Compose 可观察。revision 在该题所属数据代际内单调；Saved 只确认当前最新受理文字已可靠提交。Inactive 是该题没有本实例的编辑任务，不显示成“刚刚保存成功”；原已加载数据库内容照常显示。
- Saving 包括合并窗口与在途写入；Error 不丢最新内存文本，允许继续编辑并按既定调度产生新保存尝试。无新修改时不无限自动重试。新版本成功后，旧失败/旧重试不得覆盖内容或降级当前状态。
- updateCodeDraft 保持 draft 内存镜像，与 vm.questionDraft 的既有加载/缓存衔接，不因 Progress Flow 发射回滚输入。codeDraftEditingBlocked 在备份/替换/重置的排他边界为 true；该期间拒绝新草稿更新，UI 禁止输入，不静默丢弃已受理内容。不是普通 Saving 时禁输入。
- retryCodeDrafts(id) 重试该题最新失败版本；null 重试所有最新失败题。该操作不导航、不重试旧 payload、不触碰考试答案或便签。
- flushCodeDrafts(id) 捕获调用时该题最新 revision；null 捕获所有当前受理题的版本。立即取出合并窗口内数据提交，不等待 300ms/2000ms。直到所捕获版本或同代际更新版本可靠提交才 true；失败 false、保持 Error。调用者取消向上传播，不取消受理写入。无待写任务 true；遇到数据代际失效不能将被丢弃旧任务伪报已保存。
- 保存只改 code/notes，事务内读最新行后写或采用必要字段级 SQL；不能覆盖同期收藏、flagged、评分、计数、SRS 或其他个人字段。保持原 repo.update 事务安全；不要求为了“字段级”而无谓重写其他写入方。
- 保留 saveNotes(id,code,notes): Unit 的现有签名：更新后显式 flush，该次成功才提示“代码与笔记已保存”；失败展示且不发成功提示。
- 既有 codeDrafts.drafts 保持 questionDraft 所需语义；旧 writer 调用迁移到新接口。若保留内部兼容适配器，其 flush 必须包含合并窗口，pending 必须含未落盘版本，不能成为绕过协议的第二个写入路径。正式契约由 GPT 在实现交付时同步 API_CONTRACT，Claude 不直接访问 writer。
